The following tests are CRITICAL for validating the new sorter implementation:

1. sort.test (59 tests) - PRIMARY
   - Tests all ORDER BY variations
   - Tests ASC/DESC
   - Tests multiple column sorts
   - Tests with various data types

2. select1.test (144 tests) - SECONDARY
   - Many tests include ORDER BY
   - Tests basic sorting in queries

3. select3.test (33 tests) - SECONDARY
   - GROUP BY with ORDER BY
   - Sorting aggregated results

4. select4.test (52 tests) - SECONDARY
   - DISTINCT with ORDER BY
   - Combined operations

5. where.test (135 tests) - SECONDARY
   - ORDER BY with WHERE clauses
   - Index-based sorting

These tests MUST pass at 100% to validate the sorter opcodes:

- OP_SorterSort

- OP_SorterClose

NOTES
=====

1. Test counts are estimates based on do_test statement count
   Actual test count may vary slightly

2. Some tests may be skipped in quick mode (ISQUICK=1)
   Full test count requires all.test

3. Tests may have platform-specific behavior
   Especially threading and locking tests

4. Some tests may depend on specific Berkeley DB behavior
   DBSQL uses BDB 4.8 for storage

5. Foreign key support may be incomplete or stubbed
   fkey1.test may fail entirely

6. Authorization callbacks may be stubbed
   auth.test may have low pass rate

7. Date functions depend on implementation
   date.test pass rate depends on date support

8. TCL version is 8.5 (older)
   May have compatibility issues with newer TCL

9. All tests create files in test.db
   Need write permissions in test directory

10. Tests are not isolated
    Early crash can stop entire suite
